## Plan: `COCO_WORKSHOP.PIPELINE_LAB.SILVER_AP_INVOICES` (Dynamic Table)

**What I found**
- `COCO_WORKSHOP.PIPELINE_LAB` **doesn't exist yet**, so step 1 creates it.
- Both bronze tables have **change tracking OFF**. The dynamic table needs it for incremental refresh, and Snowflake switches it on automatically when the table's owner (SYSADMIN) creates the dynamic table, so no separate step is needed.
- The SELECT below already compiles against the source tables.
- Team decision: **solo**. This is one dynamic table plus one schema.

**Steps** (all run as SYSADMIN, the owner of the source tables)
1. `CREATE SCHEMA IF NOT EXISTS COCO_WORKSHOP.PIPELINE_LAB;` and grant `COCO_WORKSHOP_ROLE` the same privileges it has on the `USER_xx` schemas (`ALL` on the schema plus future tables, dynamic tables and views), so participants can work there.
2. Create the dynamic table:
```sql
CREATE OR ALTER DYNAMIC TABLE COCO_WORKSHOP.PIPELINE_LAB.SILVER_AP_INVOICES
  TARGET_LAG = '1 hour'
  WAREHOUSE  = COCO_WORKSHOP_WH
  REFRESH_MODE = INCREMENTAL
  INITIALIZE = ON_CREATE
AS
SELECT 'SAP' AS SOURCE_SYSTEM, INVOICE_ID AS SOURCE_INVOICE_ID, INVOICE_NUMBER,
       VENDOR_ID, VENDOR_NAME, INVOICE_DATE, DUE_DATE, INVOICE_AMOUNT, CURRENCY_CODE,
       PAYMENT_TERMS, PO_NUMBER, LINE_DESCRIPTION, GL_ACCOUNT, COST_CENTER,
       APPROVAL_STATUS, CREATED_AT,
       SAP_COMPANY_CODE AS SOURCE_ENTITY_CODE, SAP_DOCUMENT_TYPE AS SOURCE_DETAIL
FROM COCO_WORKSHOP.SOURCE_DATA.BRONZE_SAP_AP_INVOICES
UNION ALL
SELECT 'ORACLE', INV_ID, INV_NUM, SUPPLIER_ID, SUPPLIER_NAME, INV_DATE, PAYMENT_DUE_DATE,
       TOTAL_AMOUNT, CURRENCY,
       CASE TERMS_CODE WHEN 'N30' THEN 'NET30' WHEN 'N60' THEN 'NET60' ELSE TERMS_CODE END,
       PURCHASE_ORDER, DESCRIPTION, ACCOUNT_CODE, DEPT_CODE,
       STATUS, CREATION_DATE, ORACLE_ORG_ID, ORACLE_SOURCE
FROM COCO_WORKSHOP.SOURCE_DATA.BRONZE_ORACLE_AP_INVOICES;
```

**Design choices**
- **Column names** match what `AGENT_EVAL_SET` expects (`VENDOR_NAME`, `INVOICE_AMOUNT`, `INVOICE_DATE`, `DUE_DATE`, `CURRENCY_CODE`, `APPROVAL_STATUS`, `SOURCE_SYSTEM`).
- **Payment terms** are standardized to the `NET30` / `NET60` codes; this is the only value mapping.
- **Status values are not mapped.** Oracle's `VALIDATED` passes through as-is, because whether it equals `APPROVED` is still an open question.
- **Amounts stay in their original currency**, with no FX conversion. GL account and cost center codes are also kept unchanged.
- **Source-specific columns** go into two generic columns: `SOURCE_ENTITY_CODE` (SAP company code / Oracle org ID) and `SOURCE_DETAIL` (SAP document type / Oracle import source).
- **Key:** each row is uniquely identified by `SOURCE_SYSTEM` + `SOURCE_INVOICE_ID`.
- **Lag:** `TARGET_LAG = '1 hour'` keeps workshop cost low; I'm happy to change it. `INCREMENTAL` works because a plain `UNION ALL` with `CASE` supports incremental refresh.

**How I'll verify it**
- `SHOW DYNAMIC TABLES IN SCHEMA COCO_WORKSHOP.PIPELINE_LAB` to confirm the refresh mode is INCREMENTAL and the state is healthy.
- Expect 30 rows (15 SAP + 15 Oracle), split by `SOURCE_SYSTEM`.
- Confirm there are no duplicate keys and no NULLs in the core columns.
- Run 2–3 `AGENT_EVAL_SET` queries (spend by vendor, count by source system, grand total) to confirm they execute.
